# 💰 Трекер расходов

Мобильное PWA-приложение для учёта расходов и доходов: аналитика, бюджет, цели накопления, регулярные платежи, долги и ИИ-советы. Вход через Google, данные синхронизируются между устройствами через Firebase Realtime Database.

## 🚀 Быстрый старт

1. Опубликуй папку проекта на любом статическом хостинге (например, GitHub Pages, см. ниже)
2. Открой сайт и войди через Google
3. Добавь на главный экран телефона: **Настройки → Приложение → Установить** (или «Поделиться → На экран „Домой“»)

> Service Worker и вход через Google не работают при открытии файла напрямую (`file://`) — нужен http(s).

### Быстрый ввод

`обед 45` → расход 45, категория «Еда». `+зарплата 5000` → доход.
Категория угадывается по ключевым словам (заправка → Машина, аптека → Здоровье)
и по названиям своих категорий. Кнопка 🎙 — голосовой ввод (Chrome/Android).

### Фото чека

Кнопка 📷 открывает камеру или галерею. Снимок сжимается до 1400 px и уходит
модели зрения: она читает итоговую сумму, дату, магазин и подбирает категорию.
Форма добавления открывается уже заполненной — запись сохраняется только
после вашей проверки.

Снимок остаётся при операции: уменьшенная копия ложится в `users/{uid}/receipts/{txId}`
и подтягивается, только когда открываешь запись — иначе каждая синхронизация
тянула бы все чеки разом. Прикрепить или убрать фото можно в карточке операции.

> ⚠️ Фото чека уходит провайдеру ИИ — см. «ИИ» ниже.

### Долги

**Меню ⋯ → Долги.** «Дал в долг» списывает сумму со счёта, «взял в долг» —
добавляет. Возврат можно вносить частями; пустое поле суммы означает «вернули всё».
За три дня до обещанной даты и после просрочки появляется напоминание на главной.

Удаление долга из списка не трогает операции по счёту — деньги ведь правда двигались.

### Перенос остатка бюджета

Галочка в «Плане». Неистраченное за прошлый месяц добавляется к бюджету текущего,
перерасход — вычитается. Переносится только один месяц, а не вся история.
Если в прошлом месяце записей нет, перенос не считается.

### Уведомления

Приходят, пока приложение открыто или свёрнуто: системного push-сервера здесь нет,
для доставки при закрытом приложении понадобится Firebase Cloud Messaging и сервер.

## 🔥 Настройка Firebase

1. Создай проект в [Firebase Console](https://console.firebase.google.com), включи **Authentication → Google** и **Realtime Database**
2. Подставь свой `firebaseConfig` в `firebase-init.js`
3. Добавь домен сайта в **Authentication → Settings → Authorized domains**
4. Задай правила базы данных:

```json
{
  "rules": {
    "users": {
      "$uid": {
        ".read": "auth != null && (auth.uid === $uid || root.child('users').child($uid).child('members').child(auth.uid).exists())",
        ".write": "auth != null && (auth.uid === $uid || root.child('users').child($uid).child('members').child(auth.uid).exists())"
      }
    },
    "shares": {
      "$uid": {
        ".read": "auth != null && auth.uid === $uid",
        "$owner": {
          ".write": "auth != null && auth.uid === $owner"
        }
      }
    },
    "config": {
      ".read": "auth != null",
      ".write": false
    }
  }
}
```

Строчки про `members` и `shares` — это и есть совместный доступ: кого вы вписали
в `users/{ваш uid}/members`, тот видит и меняет ваши данные. Без них приложение
работает как раньше, только кнопка «Открыть» в общем бюджете скажет, что доступа нет.

### Структура данных

```
users/{uid}/transactions/{txId}   ← каждая операция отдельным ключом
users/{uid}/receipts/{txId}       ← фото чека, читается по требованию
users/{uid}/subscriptions         ← регулярные платежи и доходы
users/{uid}/goals                 ← цели накопления
users/{uid}/debts                 ← долги
users/{uid}/members/{uid}         ← кому открыт доступ к этим данным
users/{uid}/settings              ← валюта, бюджет, тема, счета, свои категории, лимиты
shares/{uid}/{ownerUid}           ← приглашения, которые видит этот пользователь
config/aiKey                      ← ключ ИИ (если нет прокси)
config/aiProvider                 ← 'gemini' или 'groq', необязательно
config/aiProxy                    ← адрес прокси (рекомендуется)
```

Старый формат (транзакции массивом) автоматически переводится в новый при первом входе.

### Совместный доступ

**Настройки → Совместный доступ.** Оба открывают приложение и смотрят свой код.
Хозяин бюджета вставляет код второго человека и нажимает «Дать доступ» — тот
увидит новый бюджет в списке и сможет в него переключиться. Переключение
меняет только путь в базе: вход, аккаунт и локальный кэш остаются своими.

Участник получает полный доступ: и читать, и писать, и приглашать дальше.
Приглашайте только тех, кому доверяете бюджет целиком.

## 🤖 ИИ: советы и чтение чеков

По умолчанию — **Gemini**: ключ бесплатный, берётся за минуту
в [Google AI Studio](https://aistudio.google.com/apikey) (нужен только Google-аккаунт),
одна и та же модель читает и текст, и фото чека.

Положи ключ в базу:

```
config/aiKey = "AQ.Ab8..."
```

Ключи Google сейчас начинаются с `AQ.`; старый формат `AIza…` тоже работает.
Приложение узнаёт провайдера по виду ключа, так что больше ничего указывать не нужно.

Чтобы вместо него взять Groq — допиши `config/aiProvider = "groq"`.
Старые узлы `config/geminiKey` и `config/groqKey` тоже понимаются.

### Имена моделей

Провайдеры регулярно снимают модели с публикации, и приложение получает
«The model does not exist». Поэтому в `AI_PROVIDERS` (`app.js`) у каждого
провайдера список моделей: перебираются сверху вниз, берётся первая ответившая.
Перестало работать — допиши новое имя в начало списка, больше нигде менять не надо.

### Прокси

Ключ в базе виден любому вошедшему пользователю — его можно вытащить
из вкладки Network и потратить вашу квоту. В папке `ai-proxy/` лежит
Cloudflare Worker, который держит ключ у себя и пускает только тех, кто вошёл
в ваше приложение. Развёртывание — в [ai-proxy/README.md](ai-proxy/README.md).

После развёртывания положи адрес в `config/aiProxy` и удали ключи из базы.

## 🎨 Правила оформления

Чтобы интерфейс не расползался, при доработках держись четырёх правил:

1. **Фиолетовый `--accent` — только то, что нажимается.** Кнопки, активные вкладки и чипсы.
   Заголовки, цифры и полоски прогресса красить им нельзя.
2. **Цвет данных = смысл.** `--accent3` доход, `--accent2` расход, `--accent4` предупреждение,
   цвет категории или счёта — только у самих данных. Отрицательный баланс всегда красный,
   даже если у счёта зелёный цвет.
   Палитра — `DATA_COLORS` в `app.js`: у каждого цвета два тона, `[тёмная тема, светлая]`.
   Насыщенные цвета «звенят» на чёрном и блёкнут на белом, поэтому в коде хранится
   **имя** цвета (`blue`, `crimson`), а нужный оттенок выдаёт `themeColor()`.
   Новые цвета добавляй парой тонов туда же, хекс в разметке не пиши.
3. **Один язык иконок.** Интерфейс — линейные SVG из `ICONS` в `app.js`
   (`ic('trash')` в шаблонах, `<span data-icon="trash">` в разметке).
   Эмодзи — только данные пользователя (категории, счета, цели) и иллюстрации пустых экранов.
4. **Размеры шрифта — из шкалы** `--fs-1`…`--fs-6` в `:root`, новые значения не добавляем.

Цветную полоску сверху носят только две карточки: остаток на главной и бюджет в «Плане».

Строка из нескольких полей на телефоне: гибкому полю нужен `min-width: 0`, иначе оно
не сожмётся ниже своей ширины по умолчанию и уедет за край.

### Выпуск новой версии

Поменяй версию в двух местах — иначе у части пользователей останется старый кэш:

1. `VERSION` в начале `sw.js`
2. `?v=` в трёх ссылках `index.html` (`styles.css`, `app.js`, `firebase-init.js`)

```bash
# заменить 20260917 на новую дату во всех файлах сразу
sed -i 's/20260917/20261001/g' sw.js index.html
python tests/run.py
```
